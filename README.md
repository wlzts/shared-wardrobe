# 共享衣柜 App 👔

基于 GitHub 的多设备同步衣柜管理应用，支持多衣柜切换和情侣/家人之间互相推荐衣服。

**零后端、零服务器**——所有数据存储在你的 GitHub 仓库中，两台设备配置同一仓库即可同步。

## ✨ 功能特性

- 👗 **多衣柜管理**：创建多个衣柜（我的衣柜、换季收纳、鞋柜等），一键切换
- 🔄 **双设备同步**：两台设备配置同一 GitHub 仓库，数据实时同步
- 💌 **互相推荐**：查看对方共享衣柜，挑选衣物并写推荐语发送给对方
- 📅 **穿搭记录**：日历视图记录每日穿搭，回顾穿搭历史
- 📊 **统计分析**：衣物数量、类别分布、穿搭频率可视化
- 📷 **衣物图片**：拍照或上传图片，自动压缩存储
- 🔒 **数据自主**：数据完全在你自己的 GitHub 仓库中，PAT 仅存本地
- 📴 **离线模式**：无网络时本地操作，恢复网络后自动同步

## 🚀 部署步骤

### 1. 准备 GitHub 仓库

本仓库已经包含完整代码，你可以直接使用当前仓库。

### 2. 开启 GitHub Pages

1. 进入仓库的 **Settings** → **Pages**
2. Source 选择 **Deploy from a branch**
3. Branch 选择 **main**，文件夹选择 **/ (root)**
4. 点击 **Save**
5. 等待几分钟后，页面顶部会显示你的网站地址，如 `https://wlzts.github.io/shared-wardrobe/`

> ⚠️ 免费账户的私有仓库无法使用 GitHub Pages。如果需要私有仓库，请升级到 GitHub Pro。公开仓库的代码是可见的，但你的衣物数据在 `data/` 目录中，建议不要在衣物名称/备注中填写敏感信息。

### 3. 生成 Personal Access Token

1. 访问 [https://github.com/settings/tokens/new](https://github.com/settings/tokens/new?scopes=repo)
2. Note 填写 `共享衣柜 App`
3. Expiration 选择合适的有效期（建议 90 天或自定义）
4. 勾选 **repo** 权限（完整的仓库读写权限）
5. 点击 **Generate token**
6. **立即复制生成的 token**（格式如 `ghp_xxxxxxxxxxxx`），关闭页面后无法再次查看

### 4. 配置 App

1. 打开你的 GitHub Pages 网站
2. 进入底部「设置」Tab
3. 填写：
   - **GitHub 用户名**：你的 GitHub 用户名（如 `wlzts`）
   - **仓库名**：仓库名称（如 `shared-wardrobe`）
   - **Personal Access Token**：刚才生成的 token
4. 点击「保存配置并测试连接」
5. 连接成功后，示例数据会自动同步到本地

### 5. 第二台设备配置

在另一台设备（手机或电脑）上：
1. 用浏览器打开同一个 GitHub Pages 网址
2. 进入设置，填写**相同的用户名、仓库名和 Token**（或对方自己的 Token，只要对该仓库有读写权限）
3. 保存后即可看到同步的数据

> 💡 如果是情侣共用，建议两台设备都使用同一个 Token，或各自生成对该仓库有 collaborator 权限的 Token。

## 📖 使用说明

### 衣柜管理

- 点击顶部衣柜名称 → 展开衣柜列表，点击切换
- 点击「+ 新建衣柜」创建新衣柜
- 点击衣柜右侧 ✏️ 编辑衣柜信息或删除
- 衣柜可见性：
  - **私有**：仅自己可见
  - **共享**：同仓库的其他用户可查看（只读）

### 添加衣物

1. 在自己的衣柜页面，点击右下角 **+** 按钮
2. 上传图片（自动压缩）、填写名称、类别等信息
3. 保存后自动同步到 GitHub

### 穿搭记录

1. 进入「穿搭」Tab
2. 点击日历上的日期 → 点击「+ 添加穿搭」
3. 从衣柜选择衣物组合，可加备注
4. 保存后日历上会标记有穿搭的日期

### 为对方推荐衣服

1. 切换到对方的**共享衣柜**（顶部衣柜列表中选择）
2. 点击右下角「💌 推荐穿搭」按钮
3. 点击选择想推荐的衣物（可多选）
4. 点击底部「确认推荐」
5. 填写推荐语，点击「发送推荐」
6. 对方在「推荐」Tab 中可以看到，选择「采纳为穿搭」或「忽略」

### 同步

- 每次打开 App 自动同步
- 每 30 秒后台自动拉取最新数据
- 点击顶部同步状态图标手动同步
- 无网络时操作保存在本地，恢复网络后自动推送

## 📁 数据结构

所有数据存储在仓库的 `data/` 目录中：

```
data/
├── wardrobes.json          # 所有衣柜的元数据
├── wardrobes/
│   ├── {wardrobeId}.json   # 每个衣柜的衣物和穿搭数据
│   └── ...
└── recommendations.json    # 所有推荐记录
```

衣物图片存储在 `images/` 目录中，以衣物 ID 命名。

## 🔒 隐私与安全

- **Token 安全**：Personal Access Token 仅存储在设备本地的 localStorage 中，不会上传到任何服务器，不会写入仓库
- **数据归属**：所有数据在你自己的 GitHub 仓库中，你完全拥有和控制
- **仓库权限**：建议将仓库设为私有（需 GitHub Pro），公开仓库请避免在衣物信息中填写敏感内容
- **清除数据**：在设置页点击「清除本地数据并登出」可清除本设备的所有缓存和 Token

## ❓ 常见问题

**Q: 两台设备必须用同一个 GitHub 账号吗？**
A: 不一定。可以用两个不同的 GitHub 账号，只要两个账号都对该仓库有读写权限（在仓库 Settings → Collaborators 中添加对方）。但简单起见，用同一个 Token 最方便。

**Q: 图片存在哪里？会占用仓库空间吗？**
A: 图片上传到仓库的 `images/` 目录。App 会自动将图片压缩到 800px、JPEG 质量 70%，通常每张 50-150KB。GitHub 仓库建议总大小不超过 1GB。

**Q: 两个人同时修改会冲突吗？**
A: 由于每个衣柜使用独立的数据文件，两人编辑各自衣柜时不会冲突。仅推荐记录可能同时写入，App 会基于最新版本合并。

**Q: Token 过期了怎么办？**
A: 重新生成一个 Token，在设置页更新即可。历史数据不受影响。

**Q: 可以在手机上用吗？**
A: 可以。这是响应式 Web App，在手机浏览器中打开即可使用。可以「添加到主屏幕」像 App 一样使用。

## 🛠 技术栈

- 纯前端：HTML + CSS + 原生 JavaScript（无框架依赖）
- 图表：Chart.js（CDN）
- 后端：GitHub REST API v3（文件读写）
- 托管：GitHub Pages
- 存储：localStorage（本地缓存 + Token）
